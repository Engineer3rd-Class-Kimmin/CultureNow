# 지원용 프로젝트 설명: CultureNow

## 문제, 접근 방법과 내 기여

남는 시간 안에 갈 수 있는 활동을 찾으려면 운영시간·이동·가격·예약을 여러 사이트에서 다시 확인해야 했다. 이 확인 과정을 줄이는 서비스를 기획했다. 개인 수행 범위는 문제 정의, 공공데이터/API 조사, 비교 분석, 데이터·판정 구조, 예비조사, 사업 가설과 MVP 검증 계획이다. 제품 개발이나 실사용 성과를 개인 기여에 포함하지 않는다.

실행 불가능한 후보를 먼저 제외하고, 알 수 없는 정보는 `확인 필요`로 남기는 설계를 선택했다. LLM은 의도 해석과 근거 설명에 사용하도록 제안했지만 실제 API와 모델을 연결한 MVP는 없다. [서비스 아키텍처](ARCHITECTURE.md)에 설계 선택과 예외 처리 원칙을 적었다.

## AI 활용과 검증

제품에서의 AI 역할은 제안 단계다. 실제 모델 품질과 비용을 측정했다고 주장하지 않는다. 과거 기획 과정 전체의 도구별 작성량은 추적하지 않았다. 이번 포트폴리오 보완, 설계 시나리오 작성·대조·실행기 작성에는 Codex를 사용했다(ai-assisted).

설계 검토는 입력 상황과 기대 처리를 먼저 별도 평가셋으로 적고 기존 문서와 대조했다. 자동 실행기는 근거 인용과 설문 집계 산술을 재확인한다. 사람이 독립적으로 판정한 평가나 구현 엔진의 성능 시험은 아니다.

## 결과와 한계

18개 시나리오 중 설계 명시 12개, 부분 명시 3개, 규칙 누락 3개였다. 체류 완료와 폐관의 관계, 자정 경계, 복귀 이동시간, 충돌한 출처의 우선순위, 데이터 유효기간과 동률 기준은 추가 설계가 필요하다. [평가셋과 결과](../evaluation/design-v1/RESULTS.md), [판정 원본](../evaluation/design-v1/cases.json), [실행 결과](../evaluation/design-v1/results.json)를 공개한다.

기존 27명 예비조사의 주요 비율 4개는 집계 산술과 일치했다. 응답 원자료의 진실성이나 시장 대표성을 새로 검증한 것은 아니다. [기존 조사와 한계](VALIDATION.md)의 해석을 유지한다.

현재 상태는 `기획 완료 · MVP 미구현 · 예비 수요조사 완료`다. 결정 시간 감소, 실제 이용 증가, 기관 구매 의향은 아직 가설이다. 실제 API·엔진 평가와 사용성 비교는 구현 후에 진행해야 한다.

## 공개 범위

개별 설문 응답자 정보, 채팅 원문과 비식별 처리 전 기획서를 추가하지 않았다. 신규 공개 자료는 합성 시나리오, 문서 근거와 집계 산술이다.
