# MVP 로드맵

## 진행 원칙

전국 단위의 많은 데이터를 먼저 모으기보다, 한 지역에서 추천 결과가 실제로 맞는지 확인한 뒤 범위를 넓힙니다. 각 단계는 기능 목록이 아니라 다음 단계로 넘어가기 위한 확인 기준을 둡니다.

## Phase 1. 데이터 MVP

### 할 일

- 대상 지역 1곳 선정
- 공공 API 2~3개 연결
- 공통 활동 스키마와 원천 추적 구조 구현
- 운영시간·기간·가격·예약정보 정규화
- 중복 활동 병합과 갱신 시점 표시

### 완료 기준

- 핵심 필드 채움률과 원천별 오류율을 측정할 수 있음
- 임의 표본을 원 페이지와 대조해 변환 오류를 확인함
- 오래된 정보와 누락 정보를 구분해 표시함

## Phase 2. Actionability Engine

### 할 일

- 자연어 조건 구조화
- 시간·운영·예산·이동 기준 Hard Filter
- 설명 가능한 초기 점수식
- 추천 근거와 원천 데이터 연결

### 완료 기준

- 준비한 시나리오에서 명백히 불가능한 후보를 안정적으로 제거함
- 잘못 제거된 후보와 불확실 후보를 따로 집계할 수 있음
- 추천 문장의 모든 사실을 원천 필드로 추적할 수 있음

## Phase 3. 사용자 MVP

### 할 일

- 자연어 입력 화면
- Top 3 결과와 추천 이유
- 지도 표시와 길찾기 연결
- 원 안내·예약 페이지 연결
- 잘못된 정보 신고

### 완료 기준

- 사용자가 별도 설명 없이 조건을 입력하고 후보를 선택할 수 있음
- 결과에서 운영시간, 비용, 이동, 출처를 확인할 수 있음
- 추천 후보가 없을 때 조건 변경 방법을 안내함

## Phase 4. 사용자 실증

### 할 일

- 기존 검색과 과제 수행 비교
- 결정 소요시간과 페이지 이동 수 측정
- 선택률, 길찾기·예약 이동률 측정
- 실제 이용 여부와 추천 오류 수집

### 완료 기준

- 탐색 시간 감소 여부를 수치로 판단할 수 있음
- 실행 불가 결과의 원인을 데이터·규칙·설명 단계로 나눌 수 있음
- 다음 지역 확장 전에 고쳐야 할 우선순위가 정리됨

## Phase 5. 지역 및 기능 확장

- 데이터 원천과 지역 확대
- 반복 이용 데이터에 기반한 개인화
- 공공기관용 수요·데이터 품질 대시보드
- 필요성이 확인된 경우에만 동행 기능의 제한적 실증

동행 기능은 추천 품질과 기본 이용 흐름이 검증된 이후 별도 안전 설계와 함께 진행합니다.

## 당장 만들 첫 번째 버전

```text
범위: 한 도시 / 활동 2~3개 분야 / 모바일 웹
입력: 위치, 남은 시간, 예산, 동행 여부
출력: 근거가 있는 후보 최대 3개
연결: 길찾기와 원 예약 페이지
제외: 결제, 자체 예약, 채팅, 전국 확대, 복잡한 개인화
```

첫 버전의 목표는 화려한 데모가 아니라 “지금 갈 수 있다”는 판단이 실제 데이터와 맞는지 증명하는 것입니다.
